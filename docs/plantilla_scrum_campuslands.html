Contenido

Este documento reúne la gestión de KarenFlix bajo la metodología SCRUM: una aplicación full-stack (Node.js + Express + MySQL en el backend y HTML, CSS y JavaScript puro en el frontend) para registrar, calificar y rankear películas, series y anime. El trabajo se realiza en pareja durante 2 sprints.

Definición de Hecho (DoD)

  • Código en una rama feature y PR aprobado por la otra persona del equipo.
  • Criterios de aceptación cumplidos y probados en Bruno.
  • Endpoint documentado en Swagger.
  • Errores con el código HTTP correcto y mensaje claro en el frontend.
  • Sin errores críticos ni credenciales en el repositorio.
  • Tarjeta movida a Hecho con su evidencia en el tablero.

HU-01 · Configuración del proyecto y base de datos
Historia Como desarrolladora, quiero configurar Node.js + Express y la conexión a MySQL con variables de entorno, para tener una base técnica segura y preparada para transacciones.
Criterios de aceptación
  • Proyecto inicializado con npm y scripts dev/start.
  • Conexión con mysql2/promise mediante un pool.
  • Credenciales solo en .env (con .env.example documentado).
  • schema.sql con claves foráneas, UNIQUE y CHECK.
  • Los errores de conexión se registran sin exponer datos sensibles.
Subtareas
  • 01.1 Crear el repo y el package.json con las dependencias obligatorias.
  • 01.2 Crear config/env.js con dotenv.
  • 01.3 Crear config/db.js (pool, Singleton) y probar la conexión.
  • 01.4 Escribir database/schema.sql (tablas normalizadas 3FN).
  • 01.5 Configurar app.js y server.js (JSON y CORS).
  • 01.6 Primer commit y rama develop.

HU-02 · Arquitectura por capas y manejo de errores
Historia Como desarrolladora, quiero organizar el código en capas aplicando SOLID y patrones de diseño, para mantener el código claro, escalable y fácil de explicar.
Criterios de aceptación
  • Carpetas routes, middlewares, controllers, services, models, config y utils.
  • Los controladores no tienen SQL y los modelos no tienen lógica de negocio.
  • Errores centralizados con AppError y errorHandler.
  • Códigos HTTP correctos (200, 201, 204, 400, 401, 403, 404, 409, 500).
  • API versionada en /api/v1 y GET /version con el paquete semver.
Subtareas
  • 02.1 Crear la estructura de carpetas.
  • 02.2 Implementar utils/AppError.js.
  • 02.3 Implementar middlewares/errorHandler.js y la respuesta 404.
  • 02.4 Crear el endpoint /api/v1/version con semver.
  • 02.5 Configurar ESLint + Prettier.

HU-03 · Registro de usuarios
Historia Como visitante, quiero crear una cuenta con nombre, email y contraseña, para poder publicar reseñas.
Criterios de aceptación
  • Email único (409 si ya existe).
  • Contraseña cifrada con bcrypt.
  • Validaciones con express-validator (email válido, contraseña de al menos 8 caracteres).
  • Rol por defecto: usuario.
  • La respuesta no incluye la contraseña.
Subtareas
  • 03.1 Modelo de usuarios (create, findByEmail).
  • 03.2 Service de registro con bcrypt.
  • 03.3 Validador de registro.
  • 03.4 Ruta POST /auth/register y su controlador.
  • 03.5 Prueba en Bruno.

HU-04 · Inicio de sesión con JWT
Historia Como usuaria registrada, quiero iniciar sesión y recibir un token, para acceder a las funciones protegidas.
Criterios de aceptación
  • Login con email y contraseña (401 genérico si fallan, sin decir cuál).
  • Token firmado con jsonwebtoken y expiración definida en .env.
  • La estrategia passport-jwt protege las rutas privadas (Bearer y Cookie HttpOnly).
  • GET /auth/me devuelve el perfil de la sesión.
  • Rate limit más estricto en /auth.
Subtareas
  • 04.1 Service de login (bcrypt.compare + jwt.sign).
  • 04.2 config/passport.js con la estrategia JWT.
  • 04.3 Middleware auth con passport.authenticate.
  • 04.4 Ruta GET /auth/me.
  • 04.5 Limitador de peticiones para /auth.

HU-11 · Gestión de reseñas con transacción
Historia Como usuaria, quiero crear, editar y eliminar mis reseñas con título, comentario y nota de 1 a 10, para compartir mi opinión.
Criterios de aceptación
  • Una reseña por usuaria y película (409).
  • Calificación entera entre 1 y 10.
  • Solo la autora edita o elimina (403).
  • Crear, editar o eliminar recalcula rating_promedio y total_resenas dentro de una transacción.
  • Si falla un paso se ejecuta ROLLBACK; si todo sale bien, COMMIT.
Subtareas
  • 11.1 Modelo de reseñas transaccional.
  • 11.2 Service con beginTransaction, commit y rollback.
  • 11.3 Validadores.
  • 11.4 Rutas POST /peliculas/:id/resenas, PUT y DELETE /resenas/:id.
  • 11.5 Probar el rollback forzando un error.
